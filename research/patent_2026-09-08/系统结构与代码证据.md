## 1. 系统实际结构及适合撰写的技术链路

现有系统具有“任务解释与编译—技能执行—候选证据确认—跟踪/重捕获—事件恢复”闭环，能具体承载用户所说的“飞往指定地点搜寻并锁定目标”。模型不是逐帧直接输出飞控量。

1. **任务语义层**：自然语言进入任务解释/Fleet 规划，形成 UAV 分配、目标语义 `TargetSpec`、搜索区域 `RegionSpec`、跟踪时长、返航位置等结构化对象。Fleet 下发给本地规划器的请求包含明确的 assignment、UAV、目标和区域；要求保持目标、区域、时长，不允许本地规划器再次解释已经明确的空间约束。[compiler.py](/home/amax/ry/vlm_drones/uav_agent/fleet/compiler.py:305)
2. **可信空间编译层**：V3 给点/区域附参考坐标系；由可信位姿执行 WORLD_ENU、HOME_ENU、UAV_START_FLU、UAV_HOLD_FLU、CAMERA_FLU 到世界坐标的变换；没有地标 grounding 或参考位姿则失败；“前后左右”缺参考系也失败。[spatial_resolver.py](/home/amax/ry/vlm_drones/uav_agent/planner/spatial_resolver.py:162)、[参考地标要求](/home/amax/ry/vlm_drones/uav_agent/planner/spatial_resolver.py:273)。HOLD 位姿只在悬停握手后增加，初始规划解析器保持不变。[HOLD 绑定](/home/amax/ry/vlm_drones/uav_agent/planner/spatial_resolver.py:142)
3. **计划校验与执行层**：`PlanValidator` 控制坐标、运动限制、超时、引用解析、恢复预算，再编译为 `TaskPlan`；`MissionAgent/SkillManager` 执行 TAKEOFF、GOTO、SEARCH、TRACK、REACQUIRE、LAND 等技能。[plan_validator.py](/home/amax/ry/vlm_drones/uav_agent/runtime/plan_validator.py:138)
4. **搜索层**：区域编译器生成覆盖航点并采用指定入口策略；已有圆、矩形、扇区、多边形、走廊等，及割草、螺旋、扇扫等常规策略。可选 Qwen NBV 只提议区域内宏观视点，可信编译器拒绝越界或高度不一致的结果。[region_compiler.py](/home/amax/ry/vlm_drones/uav_agent/planner/region_compiler.py:90)、[NBV 输出约束](/home/amax/ry/vlm_drones/uav_agent/planner/region_compiler.py:179)
5. **感知及身份确认层**：生产路径为外部 YOLO 服务、BoT-SORT、同帧 RGB-D 属性证据、测量/估计器、候选确认协调器、`TargetEstimate`。Qwen 可低频补充语义或新 tracker ID 重捕获审查；Oracle 单独授权和标记，不能自动回退。[README](/home/amax/ry/vlm_drones/uav_agent/README.md:89)
6. **闭环控制层**：SEARCH/REACQUIRE 只能由可见、已确认、非纯预测、有当前 3D 位置的估计完成；TRACK 允许既有目标的短时预测，但预测不刷新真实最后可见时间。目标丢失后进入限次数、限时重捕获，重新通过候选确认，再恢复原逻辑目标身份。[search.py](/home/amax/ry/vlm_drones/uav_agent/skills/search.py:899)、[track.py](/home/amax/ry/vlm_drones/uav_agent/skills/track.py:132)、[reacquire.py](/home/amax/ry/vlm_drones/uav_agent/skills/reacquire.py:193)

“锁定”应定义为**视觉候选通过身份确认、生成稳定目标标识并允许跟踪控制的状态转换**。

## 2. 最适合主张的现有技术组合：异步语义证据—候选生命周期—当前量测的联合锁定

### A. 异步语义结果有真实多字段门控，非仅时间戳过滤

`VisualReviewCoordinator._collect_stale_reasons` 独立比较：worker stale、任务 ID、计划版本、当前步骤 ID、当前目标 ID、源观测年龄、源帧是否存在、request ID、review ID。调用处有任一过期理由即不进入模型解析；只有 gate 模式、协议正确、非 stale 的结果才可能缓存到候选语义证据。见 [完整校验函数](/home/amax/ry/vlm_drones/uav_agent/agents/visual_review_coordinator.py:2111)、[接收校验](/home/amax/ry/vlm_drones/uav_agent/agents/visual_review_coordinator.py:1284)、[缓存资格](/home/amax/ry/vlm_drones/uav_agent/agents/visual_review_coordinator.py:1395)。

这些约束的技术问题是：VLM 计算期间无人机/目标继续移动、步骤改变或计划修订，迟到的正确分类不能授权当前错误对象的跟踪。可实验注入不同延迟、计划切换与候选切换，测量陈旧结果误接纳数和误锁率。

### B. 候选重用有证据代际隔离

候选库有 PROVISIONAL/UNDER_INSPECTION/VERIFIED/REJECTED/STALE 状态以及拒绝冷却期。同 candidate ID 在 REJECTED/STALE 后重新出现时，重新设 first_seen 时间，清空旧 bbox/frame/confidence/tracker/review 历史；协调器重置短轨迹和语义候选统计。见 [candidate_bank.py](/home/amax/ry/vlm_drones/uav_agent/perception/candidate_bank.py:250)、[生产重置调用](/home/amax/ry/vlm_drones/uav_agent/perception/target_perception_coordinator.py:1182)。

候选审查缓存另保存 first_seen epoch；读取时重新核对当前候选状态、epoch 和审查观测时间。生产层还拒绝早于候选新 epoch 的外部 provider 结果。见 [缓存 epoch 检查](/home/amax/ry/vlm_drones/uav_agent/agents/visual_review_coordinator.py:507)、[外部 provider 保护](/home/amax/ry/vlm_drones/uav_agent/perception/target_perception_coordinator.py:1893)。因此不是只把字符串 candidate ID 作为永久可信身份。

### C. 最终确认有多证据一致性约束和显式 pending 状态

候选确认器要求短轨迹、语义、身份三种证据 candidate_id 一致；语义目标描述必须与当前任务一致；证据不能早于候选出现，须满足检测→短轨迹→语义→身份的时间顺序；身份一致观测数不得超过短轨迹总数。默认至少 3 帧、0.5 秒、各置信度阈值满足才 LOCKED；负证据拒绝，正但不足的证据继续 PENDING。见 [confirmation.py](/home/amax/ry/vlm_drones/uav_agent/perception/confirmation.py:43)、[一致性校验](/home/amax/ry/vlm_drones/uav_agent/perception/confirmation.py:173)、[决策](/home/amax/ry/vlm_drones/uav_agent/perception/confirmation.py:217)。

生产协调器在首次获取和重捕获确认前还要求**当前有限 3D 测量**；不能仅凭 detector+语义匹配或预测位置变为 LOCKED。见 [current 3D guard](/home/amax/ry/vlm_drones/uav_agent/perception/target_perception_coordinator.py:1502)。该处是已有门控，不应与尚未晋级的新 geometry_v2 RGB-D guard 混淆。

`TargetManager.lock()` 和 `mark_reacquired()` 的直接视觉入口明确拒绝调用，确认只能经内部受验证状态转换。重捕获重新确认的 target_id 必须等于之前保留的逻辑身份。[target_manager.py](/home/amax/ry/vlm_drones/uav_agent/target/target_manager.py:165)、[重捕获身份不变](/home/amax/ry/vlm_drones/uav_agent/target/target_manager.py:223)

### D. 已确认身份与实时可见测量分离

`TargetEstimate` 同时区分 confirmed / visible / predicted_only；纯预测禁止 visible=true。[target_estimate.py](/home/amax/ry/vlm_drones/uav_agent/common/target_estimate.py:107)

SEARCH 完成需 visible、confirmed、非 predicted_only、3D 位置及同步 camera pose；REACQUIRE 还必须目标 ID 匹配。TRACK 可用既有目标的短时预测位置控制，但仅新真实可见帧、且在原失联截止时间之前，才刷新 last_seen；按测量时间而非到达时间更新。迟到帧不能复活已越过失联期限的 TRACK。[SEARCH](/home/amax/ry/vlm_drones/uav_agent/skills/search.py:899)、[REACQUIRE](/home/amax/ry/vlm_drones/uav_agent/skills/reacquire.py:193)、[TRACK 期限与量测年龄](/home/amax/ry/vlm_drones/uav_agent/skills/track.py:192)

未确认新 tracker 的感知结果也不能替换已锁定身份的控制观测；只有匹配 target_id 且 confirmed 的估计进入既有控制流。[控制观测过滤](/home/amax/ry/vlm_drones/uav_agent/perception/target_perception_coordinator.py:2022)

### E. 重捕获重新证实身份，而非新框直接续跟

REACQUIRE 将最后位置按常速度和失联时长外推，前往预测位置附近扫描，受超时限制。[reacquire.py](/home/amax/ry/vlm_drones/uav_agent/skills/reacquire.py:78)

同 tracker ID 可用稳定轨迹一致性；新 tracker ID 在开启 gate 时需有历史参考帧的 Qwen 复核，并校验 bbox 匹配；关闭该 gate 时已有颜色证据 + 当前位置与最后确认状态的运动预测距离 + 预测时间窗路径，任一证据缺失继续 CANDIDATE。[身份策略选择](/home/amax/ry/vlm_drones/uav_agent/perception/target_perception_coordinator.py:1742)、[确定性新 tracker 证明](/home/amax/ry/vlm_drones/uav_agent/perception/target_perception_coordinator.py:1815)、[参考帧复核适配器](/home/amax/ry/vlm_drones/uav_agent/perception/visual_evidence.py:637)

若重捕获候选被拒绝，恢复原目标的身份、最后位置、速度与时间，继续 REACQUIRING；初次 SEARCH 候选被拒绝则清空候选目标数据，回 SEARCHING。[拒绝恢复](/home/amax/ry/vlm_drones/uav_agent/target/target_manager.py:283)

**建议说明书主线**：无人机在结构化指定区域搜索时，为视觉候选建立独立证据生命周期；异步语义结论经任务/计划/步骤/目标/请求匹配和候选代际匹配后，与短轨迹、身份一致性和当前 3D 测量联合授权锁定；预测值只用于有限续跟，禁止用于首次锁定和重捕获成功；失联后保留原身份重新确认。技术效果可围绕迟到误锁、候选 ID 重用误锁、预测假复活、重捕获换人/换物展开，而不能只写“使用大模型进行搜索”。

## 3. 明显未覆盖或尚未启用的边界

1. **缓存消费未完整绑定当前计划版本——重要**：当前实现对“正在返回的异步结果”有完整版本检查；但路由变化时仅 reset 共识、gate 目标和负 streak（[732 行](/home/amax/ry/vlm_drones/uav_agent/agents/visual_review_coordinator.py:732)），没有清空已接受候选缓存。`latest_candidate_review()` 只检查候选状态/epoch/时间，未再次检查缓存 `review.mission_id/plan_version` 与当前 `_route`。`QwenSemanticVerifierAdapter.from_review()` 接收当前 target_spec 并据其填入描述，也未检查原审查与当前任务版本关系（[569 行](/home/amax/ry/vlm_drones/uav_agent/perception/visual_evidence.py:569)）。因此不能声称“所有缓存语义证据消费前均有完整任务版本校验”。这是一项可明确新增、测试的改进，不是现状事实。
2. **不确定性动态有效期未见实现**：已有 fixed max_result_age_s、max_prediction_age_s、max_position_jump_m；没有发现按目标速度/协方差/相机运动/候选间距动态计算语义证据可授权窗口。可提炼为后续“语义有效期和运动不确定性联合门控”，但需补公式和实验。
3. **歧义类别驱动主动观测未证实**：有自适应 NBV 的可选实现，依据 RGB、覆盖率和可信区域；没有看到“颜色模糊→改照明/方位、尺度不足→接近、遮挡→侧移、同类身份冲突→多视角复核”的明确诊断到动作策略。此项可作为拟增加发明点，不应说现已完成。
4. **V3/NBV 非默认启用**：README 明确默认 `v2 / linear / strict / disabled`；V3 需 `--planning-contract v3`，NBV 需 `--enable-qwen-next-best-view`。[README](/home/amax/ry/vlm_drones/uav_agent/README.md:554)
5. **图程序局部补丁不是完整端到端障碍演示**：`ProgramPatch` 已实现 mission/UAV 路由、base_version、已完成前缀不可修改、替换边只能来自新后缀、返回新不可变程序的原子操作。[program_patch.py](/home/amax/ry/vlm_drones/uav_agent/planner/program_patch.py:222)。协调器有 PATH_BLOCKED→HOVER→异步 Qwen patch→验证发布，失败取消降落。[program_patch_coordinator.py](/home/amax/ry/vlm_drones/uav_agent/agents/program_patch_coordinator.py:119)。但 CLI 禁止 graph+gate 和 graph+obstacle，grounded 障碍几何尚未接到该 coordinator。[启动限制](/home/amax/ry/vlm_drones/uav_agent/scripts/run_dynamic_visual_mission.py:481)。只能写已实现的基础框架/受限实施例，不能把 graph 障碍闭环写成已完成。
6. **多机目标去重局限于逻辑任务 ID**：SharedTargetRegistry 是预绑定 assignment→UAV→target_runtime_id 的 claim 允许表。相同已注册 ID 冲突按 priority、uav_id、assignment_id 仲裁，败者被悬停。[target_registry.py](/home/amax/ry/vlm_drones/uav_agent/fleet/target_registry.py:215)、[仲裁](/home/amax/ry/vlm_drones/uav_agent/fleet/target_registry.py:334)、[运行悬停](/home/amax/ry/vlm_drones/uav_agent/fleet/runtime.py:2450)。没有跨 UAV 视觉特征+空间时序关联来判断两个不同逻辑 ID 是否同一物理目标。不能宣称已实现视觉跨机身份去重。
7. **ReID 名称需谨慎**：通用 `ReIDVerifier` 仍是抛 NotImplemented 的占位（[文件](/home/amax/ry/vlm_drones/uav_agent/perception/reid_verifier.py:1)），实际生产链是稳定 tracker ID 证据、Qwen 参考帧复核、有限颜色/位置/时间重绑定；不是通用训练好的外观嵌入 ReID 系统。
8. **感知 profile 启用状态**：多机 cube YAML 目前 geometry 是 isaac_depth、Qwen review enabled=false/shadow，新 tracker Qwen 需求配置 true；需 CLI gate 选择形成对应路径。[多机配置](/home/amax/ry/vlm_drones/uav_agent/configs/multi_uav_cube_yolo.yaml:80)、[review 配置](/home/amax/ry/vlm_drones/uav_agent/configs/multi_uav_cube_yolo.yaml:203)。单机生产 temporal checkpoint 和 geometry_v2 未晋级新 guard 的区别由主研究另行审查，本报告不将多个配置拼成一个已部署系统。

## 4. 现成基础 vs 常规工程 vs 后续建议

| 技术 | 判断 | 专利使用建议 |
|---|---|---|
| 自然语言→任务拆分→到指定区域→YOLO→跟踪 | 系统已实现；大方向高度常见 | 写背景和总体实施结构，不能独立视作创新 |
| ENU/FLU 坐标变换、割草/螺旋搜索、Kalman 预测、PID/距离保持 | 常规组成技术 | 写必要实施细节，以特定组合和效果为主 |
| 异步结果多字段校验+候选新 epoch 清空证据 | 已有明确代码 | 与当前量测锁定、重捕获重新确认组合，是相对具体的候选主线 |
| 已确认身份/当前可见量测/纯预测分离 | 已有明确代码 | 说明预测不能触发新锁定和复活已过期 TRACK 的因果作用 |
| 跟踪 ID 断裂后语义+当前运动证据复核 | 已有条件分支；不同配置选择不同路径 | 避免泛称 ReID；写参考帧要求和确定性有限适用情形 |
| 已缓存语义在每次使用前完整版本再校验 | **待补** | 很贴近当前系统缺口，可加入任务版本、目标语义摘要、candidate epoch 的联合键 |
| 依据运动协方差动态调整语义证据时效 | **待补** | 和延迟 VLM 物理场景直接相关，应有明确计算公式、阈值和消融 |
| 将语义歧义原因转换为相机/机体主动验证动作 | **待补** | NBV 已有基础，但诊断映射和闭环预算需新增 |
| 视觉跨机目标同一性判定及去重 | **待补** | 工程与验证工作量大，不建议当前主专利围绕此项 |
| 通用图后缀 patch/多服务隔离/日志 | 部分实现、部分未完整集成；常规软件工程成分强 | 不宜将实现形式本身作为核心创新 |

对比试验可在同一 Isaac 场景和同一检测器下消融：直接 detector 锁定；仅多帧 tracker；多帧+语义但无版本/epoch gate；当前完整方法。专门注入候选拒绝后 ID 重用、VLM 延迟返回、计划切换、同类干扰目标交叉、遮挡重捕获、深度失效。报告错误锁定率、ID switch、旧结果接纳率、恢复成功率/时间、VLM 调用数、飞行距离；不能只用完成率。
